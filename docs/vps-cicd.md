# Zero-Touch VPS CI/CD

## Operator flow

1. Copy `deploy/config/project.env.example` to `deploy/config/project.env`.
2. Fill the real values in `deploy/config/project.env`.
3. Run `bash deploy/scripts/setup-github-secrets.sh`.
4. Push `main`.

Everything after `git push origin main` is handled by `.github/workflows/deploy.yml`.

## Single source of truth

- Human-managed source: `deploy/config/project.env`
- Secret transport to GitHub Actions: `PROJECT_ENV_B64`
- Runtime files rendered automatically:
  - `/.env.prod`
  - `/api/.env.prod`
  - `deploy/generated/nginx/*.conf`
  - observability config generated by `api/scripts/render_observability_config.sh`

Do not commit:

- `deploy/config/project.env`
- `/.env.prod`
- `/api/.env.prod`

## GitHub secrets

Required deploy secrets:

- `VPS_HOST`
- `VPS_PORT`
- `VPS_USER`
- `VPS_PASSWORD`
- `VPS_SUDO_PASSWORD`
- `VPS_DEPLOY_PATH`
- `PROJECT_ENV_B64`
- `LETSENCRYPT_EMAIL`

Optional SMTP secrets:

- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_USERNAME`
- `SMTP_PASSWORD`
- `SMTP_FROM`
- `SMTP_TO`

`deploy/scripts/setup-github-secrets.sh` reads `deploy/config/project.env`, derives `PROJECT_ENV_B64`, and updates all required GitHub secrets. SMTP secrets are pushed only when the full set is present.

## Workflow responsibilities

`.github/workflows/deploy.yml` is the control plane. It:

- checks out the private repository
- builds `fe` with Bun
- runs `go test ./...` in `api`
- installs `sshpass` and `rsync`
- syncs a source snapshot to the VPS
- uploads `.deploy.env`
- runs `deploy/scripts/provision-and-deploy.sh` remotely
- sends success/failure email notifications with `if: always()`

## Remote zero-touch deploy

`deploy/scripts/provision-and-deploy.sh` runs on the VPS and is designed to be idempotent. It:

1. decodes `PROJECT_ENV_B64` into `deploy/config/project.env`
2. renders production env and Nginx config via `deploy/scripts/render-production-config.sh`
3. renders observability config via `api/scripts/render_observability_config.sh`
4. installs or verifies Docker, Compose, Nginx, and Certbot
5. installs the HTTP Nginx site, validates DNS, and obtains/renews TLS with Certbot
6. installs the HTTPS Nginx site and reloads Nginx
7. runs `docker compose --env-file api/.env.prod -f api/docker-compose.prod.yml up --build -d`
8. health-checks local container ports and public domain endpoints

## Production topology

`api/docker-compose.prod.yml` runs:

- `frontend`
- `api`
- `postgres`
- `redis`

Public traffic shape:

- host Nginx terminates TLS
- `/` proxies to `127.0.0.1:${FRONTEND_HOST_PORT}`
- `/api` proxies to `127.0.0.1:${API_HOST_PORT}`
- `/ws` proxies to `127.0.0.1:${API_HOST_PORT}`

Internal service ports remain stable:

- Postgres: `5432`
- Redis: `6379`

## Observability

Loki configuration is explicit and de-hardcoded:

- `LOKI_SCHEME`
- `LOKI_HOST`
- `LOKI_PORT`
- `LOKI_HOST_PORT`
- `LOKI_BASE_URL`

If `LOKI_BASE_URL` is blank, the runtime derives it from `LOKI_SCHEME`, `LOKI_HOST`, and `LOKI_PORT`.

Local observability files are rendered from templates:

- `api/observability/promtail-config.yaml.tmpl`
- `api/observability/grafana/provisioning/datasources/loki.yaml.tmpl`

## Deprecated manual flow

These scripts intentionally fail fast so the repo does not drift back to manual VPS operations:

- `deploy/scripts/bootstrap-vps.sh`
- `deploy/scripts/vps-deploy.sh`

## Validation checklist

Static checks:

- `deploy/scripts/setup-github-secrets.sh`
- `deploy/scripts/push-github-secrets.sh`
- `deploy/scripts/render-production-config.sh`
- `api/scripts/render_observability_config.sh`
- `docker compose --env-file api/.env.prod -f api/docker-compose.prod.yml config`
- `docker compose -f api/docker-compose.observability.yml config`

Deploy checks:

- `fe` build passes
- `go test ./...` passes
- runner can log in with SSH password
- remote `sudo -S` works
- domain serves `/` and `/api/ping`
- TLS issuance or renewal succeeds
- success/failure email is sent from GitHub Actions
